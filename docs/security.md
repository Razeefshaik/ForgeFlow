# Local execution boundaries

Gradle verification uses `GRADLE_USER_HOME=<active-repo>/.forgeflow-runtime/gradle`, alongside isolated Go/npm/Python caches. Windows wrappers resolve through explicit local paths. Wrapper permission and network setup failures stop the workflow before code-fix retries; failed command evidence remains persisted. Current execution messages are separate from implementation summaries and update when execution resumes or changes phase.

The [issue reactor](issue-reactor.md) may recover dependency failures only within saved execution permissions. Explicit recovery can separately approve downloads. Only inherited unauthenticated loopback discard proxies on port 9 are removed from approved child environments; host settings and normal proxies remain intact. Runtime cache collisions and links fail closed before launch. Automatic npm installation requires an existing regular lock file and absent node_modules, disables lifecycle scripts, runs inside the native sandbox, and must be followed by the original required check. Neither recovery nor an agent's BLOCKED summary bypasses independent review or PR approval.

GitHub browser login uses device authorization with a registered public OAuth Client ID and explicit GitHub consent. Windows DPAPI encrypts credentials for the current Windows account outside the project. The backend verifies `/user`, saves refresh tokens encrypted, respects polling delays, and refreshes expiring tokens. Account endpoints use the existing loopback/origin/strict-JSON protections. Public account status is marked `no-store`. See [GitHub sign-in](github-sign-in.md).

The HTTP server binds numeric loopback, validates Host, rejects cross-origin writes, requires JSON and bounds bodies. Vite proxies the API on the same origin. This is a personal local application, not a public multi-user service.

Approved external clones use exclusive directories with resolved link checks, fixed public GitHub remotes, pinned commits/branches and clean Git configuration, empty hooks/templates and no submodules. Git/test/agent subprocesses use structured arguments, deadlines, bounded outputs and cancellation of the owned process tree. Partial work/evidence is retained.

Codex exec ignores user config/rules, disables MCP and multi-agent tools and uses an explicit permissions profile. Planners/reviewers/Operator are read-only; contributors and verification can write only inside their active repository. A real inside-write/outside-denial probe gates coding. Verification runtime caches and temporary folders live inside that repository. Network is disabled unless explicitly selected on start/resume. Host automation writes metadata/artifacts alongside the repo, outside the agent's writable root.

This write boundary is not a confidentiality sandbox: the installed native CLI profile permits reads required by the host toolchain. Prompts prohibit unrelated reads, and sensitive environment values are removed; do not treat an untrusted repository as a fully isolated virtual machine. Unsupported sandbox behavior blocks execution rather than silently weakening permissions.

Host Git operations validate and pin the clone configuration in read-only contribution metadata, reject later agent configuration changes and linked Git metadata, disable hooks/credential helpers/external diffs, and use a fixed submission remote. GitHub credentials stay server-side. Only explicit submission uses authentication to push to the user's fork and POST a fork/PR. Prepared commit/title/body approval, clean-worktree checks and no force push protect the submission boundary. No auto submission or merge exists. Audit/config/test history is immutable; completed agent outcomes are immutable.
